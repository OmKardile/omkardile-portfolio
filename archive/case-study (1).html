01 — Executive Summary
What this is, in 60 seconds
This is a UI/UX redesign of GitHub — the developer platform for repos, issues, PRs, and CI — built using Apple's iOS 26 design language. Every surface is a thin glass panel with light frosted blur, a GitHub-green adaptive tint, and a conic-gradient specular rim at the edge. The wallpaper behind the repo view shows through every sidebar, issue list, and slide-over, tinted by the glass. Real optical depth, not fake glassmorphism.
The goal: take GitHub's existing developer UX — repos sidebar, search topbar, RepoView with Code/Issues/PRs/Actions tabs, IssueDetail slide-over, mobile nav — and reskin it in the language Apple uses across iOS 26 and visionOS 26. The result is a developer platform that feels simultaneously precise (GitHub's hallmark) and weightless (Apple's hallmark). Code is supposed to feel light — this redesign makes that physical.
Key constraint No heavy 30–40px blur, no 60% white panels, no fake glassmorphism. Real glass means a 3px blur, a 10% brand tint (GitHub green), an inset rim, a conic-gradient specular highlight, and a green-tinted drop shadow that carries the brand color into the air.
02 — Problem & Goals
Why redesign GitHub
GitHub's current web app reads as a dense, opaque document surface. The sidebar, topbar, and tabs use solid white panels with subtle gray borders. Issue rows are flat. The whole experience feels like a 2015 dashboard — productive, sure, but visually heavy. That heaviness is the wrong emotion for a developer tool that should feel fast and modern.
The problem, in three lines
  • Opaque chrome. The sidebar, topbar, and repo header are solid white. They cover the wallpaper instead of letting light pass through. Browsing a repo feels like being in a basement.
  • Flat lists. Issue rows and file rows use only a thin border or hover background to differentiate. There is no optical hierarchy — the only depth signal is a 1px line.
  • Static surfaces. No press feedback, no touch illumination, no specular rim. The interface ignores the device's gesture model entirely.

03 — Design System
The real glass spec, ported to web
The iOS 26 / visionOS 26 design language is not glassmorphism. The defining traits are lensing (background pixels near the rim bend, not just blur), a specular rim lit from one direction, light blur (regular only 2–3px), and adaptive brand tint at ~10%. The web port keeps the visual signature and drops the optical lensing (which needs SVG feDisplacementMap on desktop Chromium only).
Glass utility class — the entire spec
/* GitHub glass: green brand tint, light blur, conic rim */ .glass { position: relative; background: rgba(45, 164, 78, 0.10); /* 10% GitHub green */ backdrop-filter: blur(3px) saturate(1.7) brightness(1.04); border-radius: 18px; box-shadow: inset 0 0 0 1px rgba(255,255,255,.12), inset 0 1px 1px rgba(255,255,255,.32), inset 0 -1px 1px rgba(255,255,255,.14), 0 12px 36px rgba(22,50,32,.24), /* green-tinted drop */ 0 2px 8px rgba(22,50,32,.12); /* contact shadow */ } /* Conic-gradient specular rim — masked to a 1.2px ring */ .glass::before { content: ""; position: absolute; inset: 0; border-radius: inherit; padding: 1.2px; background: conic-gradient(from 215deg, rgba(255,255,255,.95), rgba(255,255,255,.05) 22%, rgba(255,255,255,.05) 45%, rgba(255,255,255,.70) 60%, rgba(255,255,255,.05) 82%, rgba(255,255,255,.95)); -webkit-mask: linear-gradient(#000 0 0) content-box, linear-gradient(#000 0 0); -webkit-mask-composite: xor; mask: linear-gradient(#000 0 0) content-box exclude, linear-gradient(#000 0 0); } /* Touch illumination follows the pointer */ .glass::after { content: ""; position: absolute; inset: 0; border-radius: inherit; pointer-events: none; opacity: 0; transition: opacity .35s; background: radial-gradient(170px circle at 50% 50%, rgba(255,255,255,.34), transparent 70%); } .glass.press { transform: scale(1.025); } .glass.press::after { opacity: 1; }

Brand tint rule The 10% tint carries GitHub green (#2DA44E) into the glass. The slide-over IssueDetail pumps the tint to 16% so the panel visibly lifts above the repo view. Never tint the body of a panel with white at 60% — that reads as foggy, not glassy.
04 — Component Inventory
Five glass components, one utility class
Every GitHub surface uses the same .glass utility above. The variant is the tint: the sidebar uses the green tint at 10%, the IssueDetail slide-over uses 16%, repo tabs are flat-glass (no fill, just rim). No component redefines the spec — they all compose it.
01 · Sidebar
Repos list
Collapsible list of pinned and recent repos, with search and a New repo CTA. Each repo row is a press-scale glass item with touch illumination on pointer-down.
02 · Topbar
Search + create
Global search input, notifications bell, and a green Create button. The bar itself is glass — light blur, green tint, conic rim at the bottom edge.
03 · RepoView
Tabbed content
Tabs: Code · Issues · PRs · Actions. Below tabs: file browser, issue list with labels, or PR list. Each tab content panel is glass. Labels are glass-tint chips.
04 · IssueDetail
Slide-over panel
Right-side slide-over with title, body, comments thread, labels, and assignees. Glass-tint 16% — visibly lifts above the repo view. The most prominent glass surface on desktop.
05 · MobileNav
Bottom dock
Pill-shaped glass dock at the bottom of the mobile viewport. 28px radius, green tint, full conic rim. Five tabs: Code, Issues, PRs, Actions, Profile. The dock is the most prominent glass surface on mobile.

Optical · Depth

Interaction · Touch
Engineered press-scale + touch-illumination across all tappable glass — scale(1.025) on a cubic-bezier(.34,1.5,.64,1) spring with a 170px pointer-following radial glow on ::after, mapping GitHub's repo, issue, and PR row interactions to Apple HIG press feedback.
Slide-over · Pattern
Shipped a right-side IssueDetail slide-over in glass-tint 16% — visibly lifts above the repo view via green-tinted drop shadow, with title, body, comments thread, labels as glass chips, and assignees — backed by a Zustand store keeping it 60fps with backdrop-filter.
Build · Stack
Built end-to-end in Next.js 16 with TypeScript, Tailwind CSS 4, and a Zustand store for repo + issue state — kept 60fps with backdrop-filter by scoping blur to 3px (not 30px), avoiding the GPU cost that breaks heavy glassmorphism on long issue lists.

Don't do these
  • No "GitHub clone" — say "redesign". Clone reads as "I copied". Redesign reads as "I learned from it".
  • No fake glass — a 30–40px blur with 60% white reads as foggy, not glassy. Real glass is 3px blur, 10% brand tint, conic rim, tinted shadow. Non-negotiable.
  • No flat background — glass needs a vibrant wallpaper to refract. Add a 5-stop green-tinted radial gradient mesh to the body.
  • Don't skip the conic rim — the inset 1.2px conic-gradient ring is the signature. Without it you have glassmorphism, not iOS 26 design language.
  • No sign-in wall — recruiters won't sign in. App must be browsable in 5 seconds.
